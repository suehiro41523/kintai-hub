# UI権限設計書

## ロール定義

| ロール | 説明 |
|---|---|
| `admin` | テナント管理者。全画面・全操作が可能 |
| `manager` | マネージャー。チーム管理画面を閲覧・操作可能 |
| `employee` | 一般従業員。自分に関する画面・操作のみ可能 |

## 凡例

| 記号 | 意味 |
|---|---|
| ○ | 表示・操作可能 |
| 閲 | 閲覧のみ可能（書き込み操作のUIは非表示） |
| - | 非表示 |

## 未認証ユーザーの挙動

ダッシュボード全体（`/(dashboard)` 配下）は `layout.tsx` で `useMe()` のエラーを検知し、`/login` へリダイレクト。

## 未確認（メール未認証）ユーザーの挙動

ダッシュボード全体（`/(dashboard)` 配下）は `layout.tsx` で `useMe()`（`GET /auth/session`）の `user.emailVerified` を確認する。`false` の場合は `/login` 等へリダイレクトせず、サイドバー・ページ内容を描画する代わりに「メールアドレスが未確認です」というブロッキングメッセージ画面を表示する。

- リダイレクトしない理由：ユーザーは既にログイン済み（Cookieセッションあり）のため、未認証扱いにする必要はない
- メッセージ画面には確認メールの再送信導線（`POST /auth/send-verification-email`）を設置する。詳細は [screens/verify-email-design.md](./screens/verify-email-design.md) を参照

## 実装方針

### ページアクセス制御の実装場所

各 `page.tsx` の先頭で `useMe()` からロールを取得し、不適切なロールの場合は `router.replace('/clock')` でリダイレクトする。ローディング中は何も描画しない（レイアウトのローディング表示で代用）。

```
page.tsx
  └─ const { data: user } = useMe()
  └─ useEffect → role が不適切なら router.replace('/clock')
  └─ if (!user || !hasAccess) return null
```

### ナビゲーション制御の実装場所

`Sidebar.tsx` 内で `useMe()` のロールを参照し、各ナビゲーションアイテムを条件付きレンダリングする。`[管理]` セクションヘッダーは配下のアイテムが1件以上表示される場合のみ描画する。

### ページ内UI制御の実装場所

各 `page.tsx` または子コンポーネントで `useMe()` のロールを参照し、権限のないボタン・タブを条件付きレンダリングで非表示にする。
